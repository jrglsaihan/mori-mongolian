安装与开始

  1. 解压 Mori-macOS-universal.zip，打开 Mori.app。也可自行放入“应用程序”。
  2. 本包含 Apple Silicon 与 Intel 架构，最低编译目标 macOS 13。已在当前 Apple Silicon Mac 运行测试；Intel 与旧系统尚未实机验证。
  3. 应用只有本地临时签名，未做 Apple Developer ID 签名与公证。另一台 Mac 可能出现安全提示；仅在确认来源可信后，通过系统“隐私与安全性”允许此应用，不要关闭系统安全保护。
  4. 打开后从字体下拉框选择已安装的蒙古文字体。点击“打开”导入 TXT，明确字节编码与蒙古文约定。
  5. 用“保存”导出 .mglx，保留富文本、配置及导入原始字节；快捷键 ⌘S。恢复副本不能替代正式文件保存。

本次实现

编辑与排版

  • 真正的 vertical-lr 竖排：上→下，列左→右
  • 标题、正文、列表、粗体、斜体、下划线、颜色、撤销/重做
  • 文档级字体、字号、行距与对齐；横向连续画布、缩放和辅助线
  • 查找/全部替换；FVS、MVS、NNBSP、ZWJ 等控制字符插入与码点查看

Mac 本地能力

  • AppKit 菜单、文件对话框、离开前未保存提醒
  • 枚举 557 个本机字体字形；44 个通过蒙古文样本码位检查，47 个覆盖测试私用区码位
  • 已发现 Menk StdEx / Menksoft 等本机字体；商业字体没有复制或打包
  • 原生输入法组字事件接入，不在组字过程中转换正文
  • TXT / HTML 导出，系统打印与另存为 PDF 入口

GB18030属于文件字节编码层，与蒙古文名义字符、字形约定及字体塑形是不同问题。本版本导入使用系统 GB18030 解码器，已测试基本中文和蒙古文四字节样本；未完成 GB18030-2022 及修改单完整符合性验证。TXT导出统一为UTF-8。

转换安全与尚缺功能

实际测试发现，示例词 ᠮᠣᠩᠭᠣᠯ 经过当前开源转换引擎往返后，名义字母并不相同。因此转换功能只预览和导出副本，不替换原文，并明确显示往返校验失败警告。引擎无警告、字形相似都不代表文本无损。
  • 输入法：已实现标准组字生命周期接入；蒙科立、蒙文企业输入法等仍需具体厂商、版本和真实样本逐个验收。Windows输入法不会因添加编码适配而直接在Mac运行。
  • Word能力：DOCX互转、表格、修订、评论、自动分页尚未实现；当前是单文档横向连续画布。
  • PDF：系统打印入口已接入，长文自动分页与PDF字形保真未完成验收。请检查打印预览；不能据此声称Word级印刷排版。
  • 更广字符集：托忒、锡伯、满文完整转换不在本次已验证范围。
  • 恢复副本：保存于本机 ~/Library/Application Support/Mori/draft.mglx，仅保留最近工作区；不是多版本历史。

验证结果

21/21 核心测试、28/28 原生编辑器检查通过。覆盖Unicode控制字符、UTF-8/UTF-16、GB18030样本、非法输入拒绝、文档序列化、码点统计、转换警告、撤销/重做、跨格式查找、组字确认键保护、原生字体枚举及隔离恢复副本回读。原生界面截图来自真实WKWebView。

这些测试不是标准认证，也不是企业输入法认证。原生恢复副本测试使用隔离内存，不触碰用户恢复文件；文件面板/磁盘故障及实际打印需要下一阶段人工验收。

源码与开源来源

源码目录 mori-mongolian/：src/ 编辑器、native/ Swift应用与构建脚本、vendor/ 离线转换引擎与字体、tests/ 测试及结果。开发时先安装 package.json 依赖，执行 npm run build:web，在项目父目录准备 outputs 后执行 npm run build:mac。构建需要Apple Command Line Tools。

  • ProseMirror：富文本编辑器，MIT
  • Satsrag/mongol-convert 0.7.1：本地WASM转换，Apache-2.0；包含mongol-norm规范化后端
  • Noto Sans Mongolian：兜底字体，SIL OFL 1.1
  • GB/T 25914-2023 标准信息：替代2010版。截图中的年份应按国标字形约定理解，而不是“Unicode 2010/2023版本”。
